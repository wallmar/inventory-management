Factory Inventory Management: Architecture

A Vue 3 single-page app talks to a FastAPI service over REST. The service keeps JSON seed files in memory and does all filtering in plain Python. There's no database, no auth, and no persistence: data resets when the server restarts.

System overview

Two processes on localhost. The browser loads the SPA from Vite on port 3000 and calls the API directly on port 8001; CORS is open (allow_origins=["*"]).

Tech stack

Deliberately small: three runtime dependencies on each side.

Frontend

  • Vue 3.4, mostly Composition API
  • vue-router 4 (HTML5 history)
  • axios for HTTP
  • Vite 8 dev server and build
  • Charts are custom SVG; layout is CSS Grid
  • Homegrown i18n (en, ja), with currency following locale (USD, JPY)

Backend

  • Python 3.11+, managed with uv
  • FastAPI with Pydantic v2 response models
  • uvicorn on 0.0.0.0:8001
  • In-memory list comprehensions instead of a query layer
  • generate_data.py regenerates the seed JSON

Testing

  • pytest and FastAPI TestClient in tests/backend
  • Covers dashboard, inventory and other endpoints
  • No frontend unit tests
  • Browser checks go through Playwright MCP

Filter data flow

The path a filter change takes, from dropdown to rendered KPI.

  1. FilterBar.vue writes to selectedPeriod, selectedLocation, selectedCategory and selectedStatus. These are module-level refs in useFilters.js, so every component shares the same state without a store.
  2. Views watch those refs and call getCurrentFilters(), which maps them to { warehouse, category, status, month }. The period is sent as month, either 2025-03 or Q1-2025.
  3. api.js builds a URLSearchParams and omits any value equal to all. Inventory only sends warehouse and category, because it has no time dimension.
  4. FastAPI runs apply_filters() for exact matches on warehouse, category and status (category and status ignore case). It then runs filter_by_month(), a substring match on order_date, with quarters expanded through QUARTER_MAP.
  5. Pydantic validates the response shape against the declared response_model.
  6. Vue stores the raw arrays in refs (allOrders, inventoryItems), and computed properties derive KPIs, chart series and tables from them.

Data model

The seed data is denormalized, with no foreign keys enforced. Records link only by string IDs and SKUs.

Core entities

  • InventoryItem: sku, name, category, warehouse, quantity_on_hand, reorder_point, unit_cost, location. An item counts as low stock when quantity_on_hand ≤ reorder_point.
  • Order: order_number, customer, items[], status, warehouse, category, order_date, expected and actual delivery, total_value.
  • DemandForecast: item_sku, category, unit_cost, current_demand, forecasted_demand, trend, period. This is the price list for restocking.

Supporting entities

  • BacklogItem: order_id and item_sku link to Order and InventoryItem. The API derives has_purchase_order at request time.
  • PurchaseOrder: backlog_item_id, supplier, quantity, unit_cost. A model exists but there's no endpoint, and the file is empty.
  • RestockingOrder: priced lines, total_cost, budget, lead_time_days (the slowest line), expected_delivery. Held in memory only.
  • Spending and Transactions: pre-aggregated summary, monthly and category data, plus 56 line items.

Known gaps

Mismatches between layers, found while mapping the code.

Client calls endpoints that don't exist

api.js defines /tasks (GET, POST, PATCH, DELETE) and /purchase-orders, but main.py implements neither. The Tasks modal and PO creation return 404.

Reports bypasses the shared layers

Reports.vue uses the Options API, calls axios with hardcoded URLs, skips useFilters and useI18n, and logs to the console on every render helper.

Backlog view is orphaned

views/Backlog.vue exists and fetches data but has no route in main.js and no nav link. Its strings are also not translated.

Month filter is a substring match

filter_by_month checks month in order_date. That's correct for YYYY-MM input but loose: any value that appears inside the date string will match.
